# Техническая документация LumiBox

Настоящий документ содержит детальное архитектурное описание подсистем, алгоритмов и спецификаций форматов данных игры LumiBox (версия alpha 1.4.6).

---

## 1. Архитектурная модель приложения

Приложение построено на базе компонентно-модульной структуры, где центральное игровое ядро координирует воксельный мир, физику, искусственный интеллект сущностей и пользовательский интерфейс.

### Цикл обновления и синхронизация тиков

В LumiBox применяется гибридная модель обновления с фиксированным шагом физики и интерполяцией рендеринга:

```
[ requestAnimationFrame ]
          │
          ▼
[ Накопление времени: accumulator += frameTime ]
          │
          ├── Пока accumulator >= fixedDeltaTime (0.05 с, 20 тиков/с):
          │     └── Engine.prototype.fixedUpdate(0.05)
          │           ├── PhysicsEngine.prototype.stepPhysics (физика игрока и тел)
          │           ├── World.prototype.fixedTick (физика песка/гравия, течение воды, дропы)
          │           └── MobManager.prototype.update (логика и конечно-автоматный ИИ мобов)
          │
          ├── Интерполяция позиций: alpha = accumulator / fixedDeltaTime
          │     └── PhysicsEngine.prototype.interpolatePositions(alpha)
          │
          ├── Кадровое обновление: GameObject.prototype.update(frameTime)
          │     ├── Вращение камеры и сглаживание взгляда
          │     ├── DayNightCycle.prototype.update (движение солнца/луны)
          │     ├── WeatherSystem.prototype.update (падение осадков)
          │     └── PlayerHand.prototype.update (анимация покачивания и удара)
          │
          ├── Отрисовка сцены: Renderer.prototype.render()
          ├── Обновление UI: UIManager.prototype.update (FPS, координаты, здоровье, хотбар)
          └── InputManager.prototype.lateUpdate() (сброс дельт мыши и тач-ввода)
```

## 2. Подсистема воксельного мира (`World.js`)

Класс `World` отвечает за хранение, процедурную генерацию, обновление блоков и построение полигональных сеток чанков.

### 2.1 Структура и индексация данных чанка

Пространство мира делится на вертикальные столбцы — чанки.
* Размерность чанка: 16 блоков по оси X, 16 блоков по оси Z, 64 (или 128) блоков по оси Y.
* Хранение вокселей чанка: одномерный плоский массив `Uint8Array` фиксированного размера `16 * 16 * CHUNK_HEIGHT`.
* Формула вычисления одномерного индекса вокселя по локальным координатам `(x, y, z)`:
  ```
  index = x + z * 16 + y * (16 * 16)
  ```
* Хранение чанков в памяти: хэш-таблица `Map<String, Chunk>`, где ключ формируется как строковые координаты чанка: `"${chunkX},${chunkZ}"`.

### 2.2 Алгоритм процедурной генерации ландшафта

Генерация выполняется на основе 2D и 3D шума Симплекса (`SimplexNoise.js`) с заданным зерном генерации (seed):
1. **Базовый рельеф (Heightmap)**: Вычисление базовой высоты поверхности через сумму октав 2D-шума:
   ```
   height = baseHeight + noise2D(x * scale, z * scale) * amplitude
   ```
2. **Биомы**: Второй слой низкочастотного шума определяет карту влажности и температуры, разделяя карту на биомы:
   * **Равнины**: пологий рельеф, поверхностный слой травы (`BLOCK.GRASS`), слой земли (`BLOCK.DIRT`), цветы.
   * **Лес**: повышенная плотность посадки деревьев (дубы, березы).
   * **Пустыня**: блоки песка (`BLOCK.SAND`) и песчаника (`BLOCK.SANDSTONE`).
3. **Пещеры и пустоты (3D Carving)**: Вычисление значений 3D-шума Симплекса на подземных уровнях. Если значение шума превышает установленный порог плотности, воксель очищается (`BLOCK.AIR`), формируя сеть каверн и туннелей.
4. **Распределение рудных жил**: Процедурный спавн жил угля (`BLOCK.COAL_ORE`) и железа (`BLOCK.IRON_ORE`) на определенных диапазонах глубин.
5. **Генерация структур**: Вызов `StructureGenerator` для посадки деревьев (стволы из `BLOCK.OAK_LOG` / `BLOCK.BIRCH_LOG` и листва `BLOCK.OAK_LEAVES`) с проверкой наличия подходящего грунта снизу.

### 2.3 Алгоритм мешинга чанков (Culled Face Meshing)

Для обеспечения высокой производительности полигональная сетка Three.js строится только для видимых граней блоков:
1. Итерация по всем вокселям чанка `(x, y, z)`. Если блок является воздухом (`id === 0`), он пропускается.
2. Проверка 6 смежных направлений (Top, Bottom, North, South, East, West):
   * Если соседний блок пуст или прозрачен (`BLOCK.properties[neighborId].isTransparent === true`), текущая грань считается видимой.
3. Добавление полигонов грани:
   * Добавление 4 вершин с позициями `(x, y, z)`.
   * Добавление UV-координат, соответствующих тайлу текстуры данного блока в атласе.
   * Вычисление значений мягкого затенения углов (Ambient Occlusion).
4. На каждую грань генерируется 2 треугольника (6 индексов).
5. Геометрия собирается в `THREE.BufferGeometry` с атрибутами `position`, `normal`, `uv` и `color` (для AO).

### 2.4 Расчет мягкого затенения углов (Ambient Occlusion)

Для каждого из 4 углов видимой грани проверяется состояние 3 смежных соседних блоков: двух прямых соседей (`side1`, `side2`) и одного диагонального (`corner`):
* Если оба прямых соседа непрозрачны: `aoLevel = 0` (максимальное затенение).
* В остальных случаях: `aoLevel = 3 - (side1 + side2 + corner)`.
* Полученное значение `aoLevel` преобразуется в множитель цвета вершины:
  ```
  AO_VALUES = [0.45, 0.65, 0.82, 1.0]
  ```
Это создает градиентные контактные тени на стыках блоков без дополнительных проходов освещения.

### 2.5 Физика вокселей: жидкости и сыпучие материалы

В методе `World.prototype.fixedTick`:
* **Сыпучие блоки (Песок, Гравий)**: Если под блоком песка находится воздух или вода, блок превращается в падающую сущность либо мгновенно перемещается вниз до обнаружения твердой опоры.
* **Течение воды**: Водные блоки распространяются по горизонтали и вниз при наличии пустого пространства в пределах допустимой дистанции потока.

## 3. Физика сущностей и коллизии (`PhysicsEngine.js`)

Физический симулятор LumiBox оптимизирован для дискретного взаимодействия AABB-коллайдеров персонажа и мобов с дискретной воксельной сеткой мира.

### 3.1 Алгоритм шага физики (`stepPhysics`)

Для каждого динамического тела:
1. **Проверка водной среды**:
   * Опрос вокселей мира в области головы (`y + 1.2`) и ног (`y`).
   * Если тело находится в воде (`isInWater = true`): к вертикальной скорости применяется демпфирование `velocity.y *= 0.9`, а сила гравитации уменьшается в 4 раза.
2. **Разрешение коллизий по оси Y**:
   * Позиция смещается: `pos.y += velocity.y * dt`.
   * Рассчитывается AABB персонажа. Находятся все твердые блоки мира, попадающие в охватывающий объем.
   * Рассчитывается глубина проникновения по вертикали. При контакте снизу: тело выталкивается наружу, `velocity.y = 0`, взводится флаг `isGrounded = true`. При ударе о потолок снизу вверх: `velocity.y = 0`.
3. **Разрешение коллизий по осям X и Z**:
   * Рассчитывается потенциальное смещение по X. Опрашиваются пересекающиеся блоки. При обнаружении преграды вычисляется минимальное смещение для устранения пересечения, а горизонтальная скорость `velocity.x` сбрасывается в 0.
   * Аналогичная операция выполняется независимо для оси Z. Раздельный расчет по осям обеспечивает гладкое скольжение вдоль стен.

## 4. Сущности и искусственный интеллект (`Mob.js`, `MobManager.js`)

Подсистема сущностей обеспечивает симуляцию живого мира через автономных неигровых персонажей (мобов).

### 4.1 Конечно-автоматная модель поведения (FSM)

Каждый моб функционирует под управлением конечного автомата со следующими состояниями:
* `STATE_IDLE` (Покой): Моб стоит на месте, таймер ожидания отсчитывает случайный интервал (1–3 секунды).
* `STATE_WANDER` (Блуждание): Моб выбирает случайное направление перемещения и двигается вперед с базовой скоростью, проверяя наличие препятствий.
* `STATE_CHASE` (Преследование): Активируется, если дистанция до игрока меньше радиуса обнаружения (`detectionRadius = 16` блоков) и между мобом и игроком есть прямая видимость. Моб ориентирует вектор скорости в сторону игрока.
* `STATE_ATTACK` (Атака): Активируется при приближении к игроку на дистанцию удара (`attackRadius = 1.5` блока). Наносит урон с заданным кулдауном.
* `STATE_HURT` (Получение урона): При получении удара моб подсвечивается красным цветом, получает импульс отдачи (knockback) назад и вверх и издает звуковой сигнал.

### 4.2 Автоматическое преодоление препятствий
В процессе перемещения моб проверяет наличие твердого блока на уровне ног по направлению движения. При обнаружении препятствия высотой в 1 блок и наличии опоры под ногами (`isGrounded === true`), моб инициирует вертикальный импульс прыжка `velocity.y = 6.0`.

### 4.3 Управление популяцией (`MobManager.js`)
* Менеджер отслеживает суммарное количество активных мобов на сцене (лимит `maxMobs = 20`).
* Спавн новых сущностей производится на расстоянии от 16 до 48 блоков от текущей позиции игрока на освещенных участках поверхности.
* Если дистанция от моба до игрока превышает 64 блока, моб автоматически деспавнится (удаляется со сцены и из физической симуляции) для экономии памяти и вычислительных ресурсов.

## 5. Выпадающие предметы и геометрия (`ItemDrop.js`, `ItemGeometry.js`)

При разрушении блоков или выбрасывании предметов из инвентаря на сцену добавляется физический объект `ItemDrop`.

### 5.1 Алгоритм попиксельной вокселизации текстуры (`ItemGeometry.js`)

Для отображения плоских спрайтов инструментов и предметов в виде объемных 3D-моделей используется алгоритм воксельной экструзии:
1. Текстура предмета 16x16 пикселей считывается в массив байтов RGBA через Canvas 2D API (`getImageData`).
2. Для каждого непрозрачного пикселя (`alpha > 128`):
   * Создается микрокуб размером `1/16` от базового блока.
   * Проверяются соседние пиксели (сверху, снизу, слева, справа). Если соседний пиксель прозрачен, строится боковая грань вокселя.
   * Лицевая и задняя грани строятся с наложением исходного цвета пикселя.
3. Все вершины объединяются в единый оптимизированный `BufferGeometry` с запеченными цветами вершин (`vertexColors`).

### 5.2 Физика и логика подбора
* Предмет выбрасывается с начальной скоростью по направлению взгляда игрока с разбросом.
* На предмет действует гравитация и коллизии с твердыми блоками.
* В состоянии покоя предмет плавно левитирует вверх-вниз по синусоидальному закону и вращается вокруг оси Y.
* **Магнетизм**: Если игрок приближается на расстояние менее 2.5 блоков, предмет плавно интерполирует свою позицию к координатам игрока (`lerp`) и при контакте перемещается в инвентарь с воспроизведением звукового эффекта подбора.

## 6. Инвентарь, крафт и плавка (`Inventory.js`, `Recipes.js`)

### 6.1 Структура данных слота
Каждый слот описывается объектом:
```javascript
{
    id: Number,     // Идентификатор типа блока или предмета (0 = пусто)
    count: Number   // Количество предметов в стопке (максимум 64)
}
```
Инвентарь состоит из 36 слотов:
* Слоты 0–8: Панель быстрого доступа (Hotbar).
* Слоты 9–35: Основное хранилище инвентаря.

### 6.2 Механика крафта
Таблицы крафта (`Recipes.js`) поддерживают две формы:
1. **Бесформенный крафт (Shapeless)**: Рецепт задается неупорядоченным набором ингредиентов (например, 1 дубовое бревно -> 4 дубовые доски).
2. **Форменный крафт (Shaped)**: Рецепт описывается 2D-матрицей 2x2 или 3x3. Алгоритм крафта сопоставляет расположенные в сетке предметы с нормализованной матрицей рецепта со смещением пустых строк и столбцов.

### 6.3 Механика плавки (Печь)
Объект печи содержит 3 рабочих слота: сырье (Input), топливо (Fuel), результат (Output).
* Каждый тип топлива в таблице `RECIPES.fuels` имеет значение времени горения в секундах (например, уголь: 80 с, доски: 15 с, саженцы: 5 с).
* Время плавки одной единицы руды фиксировано (10 секунд).
* При наличии топлива процесс плавки декрементирует таймер; по истечении 10 секунд сырье расходуется, а в слоте результата инкрементируется количество продукта (например, железная руда -> железный слиток).

## 7. Спецификация формата модулей `.lumibench`

Файлы с расширением `.lumibench` представляют собой JSON-документы, описывающие наборы пользовательских ресурсов (модификаций).

### Полная JSON-схема манифеста

```json
{
  "id": "example_mod",
  "name": "Example Modification",
  "version": "1.0.0",
  "author": "Author Name",
  "atlas": "example_mod-atlas.png",
  "textures": {
    "custom_block": { "x": 0, "y": 0, "w": 16, "h": 16 },
    "custom_item": { "x": 16, "y": 0, "w": 16, "h": 16 }
  },
  "blocks": [
    {
      "id": 200,
      "name": "custom_block",
      "isSolid": true,
      "isTransparent": false,
      "isBreakable": true,
      "lightEmission": 0,
      "texture": "example_mod:custom_block",
      "drop": 200
    },
    {
      "id": 201,
      "name": "custom_pillar",
      "isSolid": true,
      "isTransparent": false,
      "texture": {
        "top": "example_mod:pillar_top",
        "bottom": "example_mod:pillar_top",
        "side": "example_mod:pillar_side"
      },
      "drop": 201
    }
  ],
  "items": [
    {
      "id": 300,
      "name": "ruby",
      "isItem": true,
      "texture": "example_mod:custom_item",
      "maxStack": 64
    }
  ],
  "recipes": {
    "crafting": [
      {
        "pattern": [
          ["example_mod:ruby", "example_mod:ruby"],
          ["example_mod:ruby", "example_mod:ruby"]
        ],
        "result": { "id": 200, "count": 1 }
      }
    ],
    "smelting": {
      "200": { "result": 300, "count": 4 }
    },
    "fuels": {
      "200": 30
    }
  }
}
```

### Регистрация модуля в `ModuleManager.js`
1. Загрузка JSON-манифеста через HTTP `fetch`.
2. Загрузка связанного изображения атласа (`atlas`).
3. Копирование пиксельных данных тайлов в главный текстурный атлас мира.
4. Добавление блоков в реестр `BLOCK` и `BLOCK.properties`.
5. Добавление рецептов в глобальные таблицы `RECIPES.crafting`, `RECIPES.smelting`, `RECIPES.fuels`.
6. Вызов `world.reloadMaterials()` для обновления WebGL-текстур на видеокарте.

## 8. Студия LumiBench Studio (`lumiBench/`)

LumiBench Studio — специализированная веб-среда для визуального создания контента:
* **3D-вьюпорт**: Построен на Three.js с `OrbitControls` для кругового осмотра создаваемой модели куба или предмета.
* **Редактор текстур**: Попиксельный холст (HTML5 Canvas 2D) с поддержкой сетки 16x16, инструментов "Карандаш", "Ластик", "Пипетка", "Заливка" и цветовой палитры.
* **Настройка граней**: Возможность назначения индивидуальных текстур для каждой из 6 граней блока (Top, Bottom, Front, Back, Left, Right).
* **Экспорт**: Генерация готового zip-пакета или JSON-файла `.lumibench` с внедренным PNG-изображением атласа.

## 9. Подсистема сохранений (`SaveManager.js`)

Данные игровых миров сохраняются в веб-хранилище `window.localStorage`.

### Схема ключей хранилища
* `lumibox_worlds_index`: Массив метаданных всех созданных миров:
  ```json
  [
    {
      "id": "world_1728135000000",
      "name": "Survival Alpha",
      "seed": 1234567,
      "gameMode": "survival",
      "lastPlayed": 1728135123456
    }
  ]
  ```
* `lumibox_world_${id}`: Полный снимок состояния мира:
  * `player`: Координаты `(x, y, z)`, углы поворота камеры, уровень здоровья, выбранный игровой режим.
  * `inventory`: Массив из 36 слотов с идентификаторами и количеством предметов.
  * `time`: Текущее астрономическое время суток (0.0 .. 1.0).
  * `modifiedBlocks`: Хэш-таблица измененных или установленных игроком блоков в формате `"${x},${y},${z}": blockId`. Исходные чанки процедурной генерации не сохраняются целиком, сохраняются исключительно дельты изменений, что снижает объем записи в LocalStorage в сотни раз.
